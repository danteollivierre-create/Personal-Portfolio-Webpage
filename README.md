Responsive Design Approach The website uses a responsive design approach to provide an optimal viewing experience across different devices. CSS media queries, flexible layouts, relative sizing, and responsive images were implemented to ensure content adapts smoothly to various screen sizes. Navigation and page elements automatically adjust to improve readability and usability on desktops, tablets, and smartphones.

This project gave me the opportunity to strengthen both my web development and version control skills while creating a personal portfolio website. One of the main improvements I made was redesigning the overall layout to provide a cleaner, more professional appearance. I reorganized content into clear sections, improved the navigation system, and refined the visual design through better color choices, typography, and spacing. These changes enhanced both usability and aesthetics. One challenge I encountered was ensuring that the website displayed correctly across different screen sizes.Some elements initially appeared misaligned on mobile devices, requiring careful adjustments using media queries and responsive layouts. Through testing and debugging, I gained a much better understanding of responsive web design principles. I also learned valuable lessons about using branches and Pull Requests in GitHub. Working in separate branches allowed me to experiment with new features without affecting the main project. Pull Requests helped me review my changes before merging them and encouraged a more structured development process. Overall, this project improved my confidence in HTML, CSS, Git, and GitHub while giving me practical experience with industry-standard development workflows.

Building‍‍‍ this project has allowed me to not only brush up on my web development and version control skills, but also create a personal portfolio page at the same time. Mainly, I focused on redesigning the whole layout so that the look would be a bit cleaner and more professional.If I recall correctly, one of the changes I was happy with was breaking up all the elements and putting each on a different section of the screen, along with having them neatly categorized by color or font or size.On a whole, I think that the website turned out to be more useful and visually appealing after making these changes that affected its layout and overall style. Still, one problem that was difficult for me to solve with the help of only media queries and responsive layouts was how the website looked on different screen sizes. After all, the problem is that not every device displays pages the same way, and that's why mobile phones can get confused sometimes with the layout.

Debugging was quite a time-wasting job, but I think I made it all worthwhile and got a better grip of some key web design concepts through responsive design as a result.GitHub was also a big player in this adventure, since not only did I manage my source code version but also learned some other techniques like pulling requests.
For instance, being able to make branches gave me the freedom to try out some new features and at the same time, not disturb the main project at all. Besides this, a Pull Request was a way for me to go through all my changes and decide whether to bring in them or keep them as a draft, which was a bit of a self-discipline.
So all and all, this project is the best bet to increase your self-esteem while working with HTML, CSS, Git, and GitHub. Moreover, you could gain hands-on experience as well as understanding what industry standard development processes and tools ‍‍‍are.
